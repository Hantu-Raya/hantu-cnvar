Deadlock gameinfo benchmark · client 6774 · 2026-10-13

Hantu's gameinfo ran 12% faster than Sqooky and tied kaizuchanerus' minimum spec.

Hantu's averaged 111.7 FPS to Sqooky's 99.5, and 111.9 to kaizuchanerus' 110.4, on the same recorded match with the game restarted for every run and no extra cfg on the public configs, so each ran as published. Every frame was timed with PresentMon. kaizuchanerus keeps up by drawing less: with Hantu's object culling and draw distance it lost 9% (game frame counter, not PresentMon).

Correction: the previous version said two Sqooky settings cost it 9%. That came from the game's own frame counter, which undercounts with those settings on. Timed with PresentMon they change average FPS by only +1.0%; they do make 1% lows and latency slightly worse. Details

What was found

Not PresentMon Results marked like this were measured before PresentMon was added, with the game's own frame counter. For configs without Sqooky's engine settings that counter matched PresentMon within 0.4% on every run checked, and these comparisons stay within one config, so the FPS changes should hold. They have no 1% lows or latency, and they were not re-run with PresentMon.

kaizuchanerus keeps up by cullingNot PresentMon

It sets r_size_cull_threshold 1.6 (hides small objects at range, including breakables and golden statues) and r_farz / r_mapextents 4500 (a shorter draw distance). Switching those three to Hantu's values (0.9, 13999, 7000) dropped it from 110.4 to 100.6 FPS (-8.9%, both pairs agreeing). Which of the three carries most of that was not split out.

Sqooky's engine settings: no FPS cost, slightly worse lows and latency

Sqooky sets engine_accurate_input_processing_delta_time true and engine_max_ticks_to_simulate 2 (plus engine_low_latency_sleep_after_client_tick false, which the tester's auto.cfg set back to true in every run, so it was not tested). Timed with PresentMon, removing them moved average FPS from 99.4 to 100.4 (+1.0%, within noise). The 1% low rose from 64.0 to 67.2 and display latency fell from 19.4 to 19.0 ms (P99 27.1 to 26.3), consistent in both pairs.

With these settings on, the game's own frame counter read 87.6 FPS while PresentMon timed 99.4. That gap produced the earlier, wrong "9%" figure. Even without them Sqooky stays about 10% behind Hantu's.

Lines the game ignores

Both public configs set things the game never applies. They cost nothing, but they do not do what their comments say.

  • Locked ConVars. The game ignores gameinfo.gi lines for ConVars flagged gameinfo_cannot_override. Sqooky has 17, including lb_enable_lights and lb_enable_dynamic_lights. kaizuchanerus has 34, including r_shadows, r_directlighting and lb_enable_sunlight.
  • Names that don't exist. Sqooky sets 40 ConVars that client 6774 does not register, such as mat_async_shader_load and panorama_max_fps; kaizuchanerus sets 27.
  • Keys no DLL reads. Sqooky's WorldRenderer/Aggregate*, EnvironmentMapCacheSize, RenderSystem/GraphicsPipelineLibrary, SceneSystem/EnableSunlight, ShadowDepthBuffer and Particles/EnableMixedResolution are never read as settings: the names appear only as internal resource labels, or nowhere in the game's DLLs.
  • One adds latency. Sqooky's snd_mixahead 0.05 buffers 50 ms of audio; the default is 1 ms.

Mesh buffer pools: +1.7% for Hantu'sNot PresentMon

Hantu's gameinfo already reserved index and vertex buffer pools, but the game's mesh code only uses them when two MeshSystem flags are on, and they are off by default. Turning on UseIndexBufferPool and UseVertexBufferPool cut vertex buffers from about 5,670 to about 440 and used about 760 MB more video memory. All four back-to-back pairs favoured it (+3.6, +1.5, +0.5, +1.9 FPS). The Hantu's runs above include it, so the PresentMon head-to-head already reflects it.

Before you switch

The configs do not look the same

Hantu's turns off direct lighting, the skybox, fog and decals and caps textures at 128. kaizuchanerus sets r_size_cull_threshold 1.6, which hides breakables and golden statues at range, and a 4,500-unit draw distance. Part of each lead comes from drawing less, so compare the visuals as well as the numbers.

  • Hantu's was tested with its perf_r3.cfg. Some of its lines only apply with a cvar-unhide DLL in citadel/addons. The gameinfo alone ran at 104.5 FPS in the same test setup Not PresentMon.
  • The public configs were tested with their gameinfo.gi only. Lines the game ignores (locked ConVars) were left out, which changes nothing. Sqooky's addon pak and base_convars.txt were not installed.
  • The head-to-head ran without the tester's auto.cfg (moved aside for those sets; every Hantu's run read back its own values), so each config ran as written. The other findings were measured with it: its 112 settings ran after the gameinfo and replaced 9 of Hantu's lines, 9 of Sqooky's and 5 of kaizuchanerus', the same values on both sides of each comparison.
  • Two pairs per public config is a small sample. A 3% difference is about the smallest this design can resolve.
  • The scene is a CPU-bound spectator replay. Live matches add server and input work, and the latency figures exclude input.

How it was measured
  • Demo 110239551 from tick 138245, 300 seconds per run, 1600×900 windowed, same installed mods for every run.
  • Sets of four runs in ABBA order (one confirmation set in BAAB). Each run closed the game, installed that config's gameinfo.gi, relaunched and drove the replay over the developer console.
  • For the public configs an empty perf_r3.cfg replaced Hantu's, so none of its settings applied.
  • FPS = PresentMon frames ÷ the sum of their frame times, for frames the game started inside the 300-second window (PresentMon 2.6.0, game process only). CPU = process CPU time ÷ wall-clock seconds, where 1.0 is one fully busy logical core.
  • The original gameinfo.gi and perf_r3.cfg were restored and checksum-verified after each set.
